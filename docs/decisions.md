# Décisions d'architecture (1 ligne datée par décision)
- 2026-08-01 : Init du template. Stack Next.js + Supabase + Vitest + Playwright.
- 2026-08-01 : Stack scaffoldée dans le template (Next 16.2.12 / React 19.2.4 / Tailwind 4 / Vitest 4 / Playwright 1.62) + `package-lock.json` commité, pour que la CI soit verte dès le premier commit d'un nouveau projet. Contrepartie : versions à rafraîchir ~tous les 6 mois.
- 2026-08-01 : CI — gate `npm audit` bloquante sur `critical` au lieu de `high` : Next tire `postcss` et `sharp` avec des avis *high* dont le seul correctif proposé est un downgrade en Next 9. À réévaluer à chaque bump de Next.
- 2026-08-01 : Pas de `next/font/google` dans le layout — évite un appel réseau au build et une source de flakiness CI.
- 2026-08-01 : Tests unitaires dans `tests/` (Vitest + jsdom), e2e dans `e2e/` (Playwright). Playwright build et démarre l'app lui-même quand `CI=true`, `npm run dev` en local.
- 2026-08-01 : Seuils de couverture à 0 dans le template, à monter à 80/80 au premier ticket métier. Un template n'a pas de code métier : tout seuil > 0 est arbitraire et rend le repo rouge au repos, ce qui apprend à ignorer l'alerte. Corollaire : ne jamais baisser un seuil déjà atteint. Écarté : exclure `layout.tsx` de la couverture (pente savonneuse — on finit par exclure ce qui gêne) et écrire un test bidon sur le layout (ne prouve rien).
- 2026-08-01 : Scan de secrets du pre-commit limité aux lignes ajoutées (`grep '^+' | grep -v '^+++'`). Avant, il scannait tout le diff — contexte et suppressions inclus — et se détectait lui-même : éditer le hook près de la ligne du pattern faisait entrer cette ligne dans le diff en contexte et bloquait le commit sur un faux positif. Scanner les seules lignes ajoutées est aussi le bon périmètre sur le fond : on ne fuite un secret qu'en l'ajoutant.
- 2026-08-01 : Littéraux du scanner de secrets écrits en classes de caractères (`ROL[E]`, `live[_]`). Scanner les lignes ajoutées ne suffisait pas : les littéraux cherchés sont écrits dans le fichier scanné, donc toute modification du hook ajoutait une ligne qui matchait. La classe de caractères laisse la regex strictement équivalente mais casse l'auto-référence. Écarté : exclure le hook de son propre scan (angle mort permanent sur le seul fichier où un secret collé passerait inaperçu).
- 2026-08-01 : Scan de secrets insensible à la casse (`grep -qiE`) : la variante majuscules d'`api-key` passait au travers.
- 2026-08-01 : Gate local = gate CI. Le pre-commit lance `npm test -- --run --coverage`, exactement comme la CI : un gate local plus laxiste garantit des pushs cassés. Quand le seuil monte, les deux montent ensemble.
- 2026-08-07 : RLS activée sur les 3 tables du POC avec policies mono-utilisateur (`auth.uid() = user_id`). La spec listait « multi-utilisateurs et RLS » en hors-scope, `CLAUDE.md` exige la RLS sur toute table exposée : le hors-scope est relu comme visant les *fonctionnalités* multi-utilisateurs (partage, rôles, invitations), pas le verrou par défaut. Une base sans RLS n'est pas un raccourci, c'est une table publique.
- 2026-08-07 : `user_id uuid references auth.users` ajouté aux 3 tables, **dénormalisé** sur `sessions` et `debriefs`. Le modèle de la spec n'avait aucune colonne propriétaire, ce qui rendait toute policy inexprimable. Dénormalisé plutôt que joint : une policy qui joint la table parente est plus lente et plus facile à casser au premier changement de schéma. Contrepartie : cohérence `user_id` parent/enfant à garantir côté code.
- 2026-08-07 : Auth = Supabase magic link, une seule page, aucun flow d'inscription au-delà.
- 2026-08-07 : Les critères §6 comportementaux et de latence (réalisme du persona, interruptions, < 1,5 s, < 30 s) sortent du TDD et passent en protocole de passation manuelle (grille + 3 essais consignés). Ils dépendent d'un modèle non déterministe et du réseau : les transformer en tests produirait des tests flaky qu'on finirait par ignorer ou skipper. Le TDD est réservé aux contrats purs (schémas JSON, prompts, normalisation, modèle de données).
- 2026-08-07 : 4 contrats JSON figés en annexe A de la spec (`persona_json`, `scores_json`, `moments_json`, `transcript_json`). Le résumé à 4 champs de l'écran 1 est une VUE de `persona_json`, pas un second schéma — deux schémas concurrents pour un même objet finissent toujours par diverger.
- 2026-08-07 : `debriefs.score_global` duplique `scores_json.global` : colonne pour le tri et le graphique de l'historique, JSON pour le contrat. Invariant d'égalité garanti côté code et testé.
- 2026-08-07 : PII v0 — stockage des textes collés en base et nom réel du persona autorisés (mono-utilisateur, usage privé). Interdiction absolue en revanche de logguer un payload LLM, un texte collé ou un transcript. La purge/rétention des données de tiers est renvoyée en v1 (notée dans « Hors périmètre découvert »).
- 2026-08-07 : OpenAI comme unique fournisseur v0 — Realtime pour la voix, modèle texte le moins cher du catalogue pour persona et debrief. Une seule clé, une seule dépendance. Référence exacte du modèle à figer en T1.
- 2026-08-07 : Frontière de l'exemption TDD de la couche vocale = transport WebRTC/SDP/audio et le composant qui le pilote, rien d'autre. Timer, machine à états, normalisation du transcript et construction des prompts sont purs, donc testés.
- 2026-08-07 : Raccrochage de l'IA signalé par un tool/function call exposé au modèle Realtime (fallback : silence prolongé détecté côté client). Écarté : la phrase sentinelle dans le flux de parole — le modèle la prononcerait à voix haute ou la paraphraserait.
- 2026-08-07 : Debrief déclenché côté client en synchrone à la fin de l'appel. Onglet fermé pendant la génération = debrief perdu, risque accepté en v0 ; la session et son transcript restent consultables.
- 2026-08-07 : Session Realtime ouverte via un jeton éphémère généré par une route handler serveur. La clé OpenAI ne doit jamais atteindre le navigateur. Corollaire : tout accès OpenAI passe par une interface injectable, posée dès T1, pour que la CI tourne sans clé.
- 2026-08-07 : Mini-graphique de l'historique en SVG écrit à la main. Une librairie de charting pour une seule sparkline ne se justifie pas, et le hors-scope interdit le « dashboard de progression avancé ».
- 2026-08-07 : Cap de 10 minutes par appel = seul garde-fou de coût v0. Pas de quota journalier, pas de plafond de dépense.
